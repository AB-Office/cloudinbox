# Requirements Document

## Introduction
利用規約とプライバシーポリシーへの同意チェックを必須化し、法的文書の更新日付を監視して、ユーザーが既に同意した日付より新しいバージョンが公開された場合に再確認を促す機能を実装する。これにより、法的文書の更新時にユーザーに最新版への同意を確実に取得できるようになる。

## Requirements

### Requirement 1: ユーザードキュメントに同意情報を保存するフィールドを追加
**Objective:** バックエンドエンジニアとして、Firestoreのユーザードキュメントに利用規約とプライバシーポリシーへの同意日付とバージョン情報を保存できるようにしたい。そうすることで、ユーザーがいつどのバージョンに同意したかを追跡できるようになる。

#### Acceptance Criteria
1. Firestoreの`users/{uid}`ドキュメントに`legalConsents`フィールドを追加すること。
2. `legalConsents`フィールドは以下の構造を持つこと：
   - `terms`: { `consentedAt`: Timestamp, `documentVersion`: string（更新日時のISO 8601文字列） }
   - `privacy`: { `consentedAt`: Timestamp, `documentVersion`: string（更新日時のISO 8601文字列） }
3. 既存のユーザードキュメントに対しては、`legalConsents`フィールドが存在しない場合は`null`として扱うこと（後方互換性を保つ）。
4. ユーザー作成時（`onUserCreate`）には`legalConsents`フィールドを初期化しないこと（同意は明示的に取得するまで未設定とする）。
5. Firestoreのセキュリティルールを更新し、認証済みユーザーが自分の`legalConsents`フィールドを読み書きできるようにすること。

### Requirement 2: 法的文書のメタデータ（更新日付）を取得する機能を実装
**Objective:** フロントエンドエンジニアとして、Firebase Storageから法的文書のメタデータ（特に更新日時）を取得できるようにしたい。そうすることで、現在の文書バージョンとユーザーの同意バージョンを比較できるようになる。

#### Acceptance Criteria
1. Webアプリの`legalDocument.ts`サービスに、`getDocumentMetadata(documentType: DocumentType, locale: Locale)`関数を追加すること。
2. Flutterアプリの`LegalDocumentService`に、`getDocumentMetadata(String documentType, String locale)`メソッドを追加すること。
3. メタデータ取得機能は、Storageファイルの`updated`メタデータ（または`timeCreated`）を取得し、ISO 8601形式の文字列として返すこと。
4. メタデータ取得に失敗した場合（ファイルが存在しない、権限エラーなど）、適切なエラーメッセージを返すこと。
5. メタデータ取得時も認証状態を確認し、未認証の場合はエラーを返すこと。

### Requirement 3: Webアプリで同意チェックを必須化し、更新日付に基づく再確認を実装
**Objective:** Webアプリユーザーとして、利用規約とプライバシーポリシーに同意しないとアプリを使用できないようにしたい。また、文書が更新された場合は再確認を促したい。そうすることで、常に最新の法的文書に同意している状態を保てるようになる。

#### Acceptance Criteria
1. 認証成功後、メイン画面に遷移する前に同意チェック画面（`LegalConsentView.vue`）を表示すること。
2. 同意チェック画面では、利用規約とプライバシーポリシーの両方にチェックを入れる必要があること。
3. 両方のチェックが入っていない場合、「同意する」ボタンを無効化すること。
4. 同意チェック画面で「同意する」ボタンをクリックした際に、Firestoreの`users/{uid}/legalConsents`に同意日時と文書バージョンを保存すること。
5. 既に同意済みのユーザーでも、アプリ起動時に法的文書のメタデータを取得し、ユーザーの同意バージョンと比較すること。
6. 文書の更新日付がユーザーの同意日付より新しい場合、同意チェック画面を再表示すること。
7. 同意チェック画面では、更新された文書へのリンクを表示し、ユーザーが内容を確認できるようにすること。
8. 同意チェック画面をスキップできないようにすること（モーダルまたは専用ルートとして実装）。
9. ルーターのナビゲーションガードで、同意未完了のユーザーはメイン画面にアクセスできないようにすること。
10. 同意チェック画面のUIは、既存のデザインシステム（Vuetify）と一貫性があること。

### Requirement 4: Flutterアプリで同意チェックを必須化し、更新日付に基づく再確認を実装
**Objective:** Flutterアプリユーザーとして、利用規約とプライバシーポリシーに同意しないとアプリを使用できないようにしたい。また、文書が更新された場合は再確認を促したい。そうすることで、Webアプリと同様に常に最新の法的文書に同意している状態を保てるようになる。

#### Acceptance Criteria
1. 認証成功後、メイン画面に遷移する前に同意チェック画面（`LegalConsentScreen.dart`）を表示すること。
2. 同意チェック画面では、利用規約とプライバシーポリシーの両方にチェックを入れる必要があること。
3. 両方のチェックが入っていない場合、「同意する」ボタンを無効化すること。
4. 同意チェック画面で「同意する」ボタンをクリックした際に、Firestoreの`users/{uid}/legalConsents`に同意日時と文書バージョンを保存すること。
5. 既に同意済みのユーザーでも、アプリ起動時に法的文書のメタデータを取得し、ユーザーの同意バージョンと比較すること。
6. 文書の更新日付がユーザーの同意日付より新しい場合、同意チェック画面を再表示すること。
7. 同意チェック画面では、更新された文書へのリンクを表示し、ユーザーが内容を確認できるようにすること。
8. 同意チェック画面をスキップできないようにすること（専用画面として実装）。
9. ナビゲーション制御で、同意未完了のユーザーはメイン画面にアクセスできないようにすること。
10. 同意チェック画面のUIは、既存のMaterial Designと一貫性があること。
11. 既存の`LegalDocumentScreen`を活用して、文書表示機能を再利用すること。
