# CloudInbox 静的LP ワイヤーフレーム（1ページ）

目的：Gmailの「外部メール取り込み（POP）」廃止の代替として、CloudInboxの価値（どこでも読める／クラウド受信箱／暗号化＋鍵管理）を1ページで伝え、CTAに誘導する。

---

## 0. グローバル要件

- LPは1ページ構成（セクション分割）
- CTAは最低2箇所（Hero / 最終セクション）
- 「Gmailの外部メール取り込み機能の廃止（2026年1月以降）」を前提課題として明示
- POP3のメールが「クラウド上のメールボックス」に集約され「どこでも読める」を主要訴求にする
- セキュリティは「暗号化」と「鍵管理」を分けて分かりやすく説明する
  - Google Cloud KMS：暗号化の鍵の保管・管理
  - Secret Manager：パスワード等の機密情報の保管・参照制御
- 難しい専門用語の連発は避け、短文＋図解（イメージ枠）で理解できる構成にする

## 3. 解決策提示（What is CloudInbox）

### 目的
CloudInboxを一言で定義し、価値を3点に絞って提示。

### コンテンツ
- H2：
  - CloudInboxは「外部メール取り込み」の代替です
- リード文：
  - CloudInboxは、POP3メールを安全に受信し、クラウド上のメールボックスに集約するサービスです。
- 3カラム（アイコン＋見出し＋短文）
  1) POP3メールを集約
     - 外部メールを1つの受信箱に
  2) どこでも同じ受信箱
     - PC・スマホ・タブレット対応
  3) 暗号化で安全
     - クラウド上でも安心

## 4. 仕組み（How it works）

### 目的
「難しそう」を消し、導入イメージを持たせる。

### コンテンツ
- H2：
  - 仕組みはシンプルです
- ステップ（縦フロー推奨）
  - STEP 1：外部メール（POP3）の接続情報を登録
  - STEP 2：CloudInboxが定期的にメールを受信
  - STEP 3：暗号化されたクラウド受信箱に保存
  - STEP 4：ブラウザやスマホから閲覧

### 図のプレースホルダー
- 「外部メールサーバ →（POP3）→ CloudInbox →（暗号化保管）→ ブラウザ/スマホ」

## 5. メイン価値①（クラウドメールボックス）

### 目的
端末依存からの解放を、生活感のある言葉で訴求。

### コンテンツ
- H2：
  - 受信箱は、もう端末に縛られません
- 本文：
  - CloudInboxでは、メールはクラウド上の受信箱に保存されます。
  - ・会社PCでも／・自宅PCでも／・スマホでも、いつでも同じ受信箱を見ることができます。
- 補足（小さく）：
  - 端末に依存しないため、PC買い替え時も設定不要です。

### コンテンツ

- 本文：

  - ・見落としを防ぐ
  - ・受信管理がシンプルに

## 7. セキュリティ（重要セクション）

### 目的
「パスワード預けるの不安」「クラウドは怖い」を解消して比較優位を作る。

### コンテンツ
- H2：
  - メールは「暗号化」されて保存されます
- リード文：
  - CloudInboxでは、メール本文を暗号化した状態で保管します。第三者が内容を読むことはできません。

### H3：暗号化と「鍵管理」は別物です
- 説明：
  - CloudInboxでは、暗号を解く「鍵」をGoogle Cloudの専用サービスで管理しています。

### 2カード（並列）
- カード1：Cloud KMS（鍵の金庫）
  - 見出し：Cloud KMS
  - 1行説明：暗号化の鍵を安全に保管・管理
  - 箇条書き：
    - ・鍵のローテーション
    - ・アクセス制御
    - ・監査ログ
- カード2：Secret Manager（機密情報の保管庫）
  - 見出し：Secret Manager
  - 1行説明：パスワードなどの機密情報を安全に保管
  - 箇条書き：
    - ・コードに直接保存しない
    - ・必要な処理のみ参照可能

### 補足（小さく）
- 鍵やパスワードを、アプリやデータベースに直接保存することはありません。

### 図のプレースホルダー（推奨）
- 「メール本文（暗号化）」「鍵（KMS）」「機密情報（Secret Manager）」を分けた簡易図
